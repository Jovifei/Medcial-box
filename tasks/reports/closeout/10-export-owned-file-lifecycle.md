原生实现有三种不同所有权：应用生成的原始文件、`share_plus` 自己复制的缓存、接收方保存的文件。Android 锁定插件把原始文件复制至自己的 `cache/share_plus` 后启动分享，后续分享会清理其缓存，但不会删除应用原始文件。本轮只清理第一种，不尝试回收后两种。

## 实现与安全边界

1. `ExportTemporaryStore` 仅登记自己实际创建的文件；每次创建独立随机目录及随机 128-bit 文件名。扩展名白名单；JSON `backupId` 仅作为内容，不进入路径。随机文件名还避免不同操作在原生插件按 basename 复制后复用同一 URI。
2. 身份代次同步作废。写入失败/部分写入、页面取消和普通结束均释放原始文件；身份清理等待已开始写入，不让晚写回填。清理失败保留精确所有权，后续身份清理可重试。
3. 对已进入原生调用的文件保留租约，直到原生 Future 返回。退出不等待分享窗口，也不会过早删除其原始文件。新的并发分享被明确拒绝，不排队跨身份重放。已发送至原生的操作不能撤回。
4. 删除只针对已登记的精确路径，拒绝被替换成符号链接的目录，不递归清空目录；无关文件、其他目录及符号链接目标保留。不会扫描、清空共享临时目录或插件缓存。选来恢复的文件只读，不登记为导出文件、不删除。
5. 复制、导出、备份与恢复在相关 await 后检查页面及身份。恢复仍须当前身份明确确认；失效的选择/读取/预览/确认不能变成新身份写入。正常确认、取消流程保留。
6. 原生选择、取消、不可确认分别提示，选择目标不等于送达。原生结果不会被临时文件删除失败覆盖，清理失败独立重试/提示。

### 原生适配器的明确维护约束

`ExportFileShare` 是一个仅支持本应用“一个已写好文件”的小型原生桥。锁定 `share_plus 13.3.0`、`share_plus_platform_interface 7.2.0`。其通用 Dart API 在文件参数整理中有 await，身份可能在最终 native 调用前变化；本桥同步生成既有参数，紧邻 native 调用做最终身份检查。

- 通道：`dev.fluttercommunity.plus/share`，方法：`share`
- 参数只有 `paths`、`mimeTypes`、`subject`、`text`；文件数组固定一项，验证必要非空参数
- null 或插件 unavailable 常量映射为不可确认，空字符串映射为取消，其他字符串映射为选择目标；PlatformException 保留
- 原生 Android 插件、复制路径和分享生命周期不变；无插件源码修改
- 测试与真实 `MethodChannelShare` 比较完整参数和结果，覆盖同一事件循环内身份作废的 native 调用顺序。依赖版本变化会令显式版本门禁失败，必须重新核对后才更新常量；不能仅删掉测试

公开 `SharePlus.share` 的额外校验涉及空文本、空文件数组、URI/文本组合及文件名覆盖数量。本应用只传一份已生成文件与固定非空文本，不接受 URI/覆盖数组。并发保护由共享文件存储提供，比插件用 unavailable 替换前一次结果更保守。

### 明确未覆盖

所有权登记目前只在进程内。**进程被杀、崩溃或重启后的原始文件遗留，以及旧版本已生成的根目录文件，不会被本轮自动扫描清除。** 普通页面中断与进程死亡不是同一验收。若 C4 要求跨重启清理，仍需独立的精确所有权持久登记与恢复设计；不能通过宽泛文件名前缀删除冒充实现。

Android `getTemporaryDirectory` 沿用应用缓存位置。本轮没有改 AndroidManifest、存储权限、chmod、系统设置或外部存储。原生插件副本、接收方副本、OS 回收时间和已开始分享均不保证被退出撤回。
