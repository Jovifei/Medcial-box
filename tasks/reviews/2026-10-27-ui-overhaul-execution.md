状态：源码及隔离环境验证完成，固定候选及交付进行中；不是上线或真机验收结论。基线为 `21428be477f914c791408db329d7b3bd6bfd6bb5`，分支 `codex/ui-overhaul-p0-20261026`。源码候选版本 `1.1.0`、Android build `14`；固定提交身份另见候选清单。

## 实施范围

- 微信小程序与 Flutter 保留“药箱 / 用药计划 / 我的”三个一级入口，原待处理入口并入药箱；旧链接保留兼容。首页家庭入口进入家庭管理，成员、邀请和切家集中处理。
- 药品详情突出封面、名称、库存与有效期；录入先拍照/扫码或填写药名，次要资料折叠，原功能与已有药品数据保留。保存当前药品不会再删除其他未完成照片草稿。
- 多张照片分图核对，标示候选来源与待核对状态；冲突需要人工选择，人工修改和主动清空优先。照片和库存使用稳定身份关联，删除不同库存不能把照片转到错误批次。
- 增加来源 API、权限和并发控制；逐图文本与警告在服务支持时可重读，离线/失败时原意图和照片回执保留。药品版本变化但来源及批次身份可确认时，经用户核对可重新同步；多人并发修改了来源正文、旧图片不可核对等情况保守阻断并保留内容，尚无自动合并流程。
- 账号或家庭变化时，编辑页和资料页隐藏旧家庭内容；小程序异步原图请求不会在身份变化后再打开。微信原生图片预览一旦已由系统打开，当前接口没有经验证的程序化关闭能力，不能声称已覆盖这一步。
- 备份默认包含库存与已保存识别来源；明确选择“仅库存”时不含逐图识别结果。两种备份均不含私有照片原件、单独保存的个人剂量备注或凭证。

## 已知边界与交付门禁

1. 默认完整 JSON 备份超过 12 MiB 会明确返回 413，尚无完整分卷备份；用户可显式选择仅库存备份，不可将其称为完整备份。后续完整分卷需不可变清单、各卷摘要与顺序校验、全部齐全后的一次事务恢复和防重。
2. 现有旧 API 不认识来源资源与新备份范围；客户端必须明确降级/保留待同步，不可静默报告已同步。完整新备份含来源时旧服务可能拒绝恢复，仅库存 v2 由旧版校验代码接受，旧服务实际恢复仍未测。
3. 新能力依赖 `035_photo_recognition_evidence.sql`。部署前须完成当前家庭数据保全、迁移/恢复演练、回滚方案及统一实例版本检查；不可混用新旧 API 实例。此轮未部署或运行生产迁移。
4. Android Release 使用 `--no-pub` 的首轮构建失败：现有本机生成的插件注册文件仍包含仅供测试的 `integration_test`，而 release 构建排除了该插件。使用 E 盘依赖缓存重生成后构建通过，包名 `com.joviluma.home_medicine_flutter`、版本 `1.1.0`、构建号 `14`；`apksigner` 确认包未签名，不能安装分发。当前构建 SHA-256：`9e395a45a867108193f7c81f2f5b15a002f1bcda7c78be6af63d497d06d2abf9`。固定提交后的包还需与源码身份重新核对。
5. 本机 `android-build-release` 的 `verify_apk.ps1` 对该 Debug APK 返回了错误的 `debuggable=false`；aapt2 badging 与 manifest 均明确为 true。今后需直接交叉核验，不能依赖该结果批准安装。
6. 当前 adb 未发现设备；未安装、未清空任何手机数据，未完成双手机、真实识别或更新覆盖验收。小程序未上传、未提交审核、未正式发布；真实服务的镜像 SHA 尚未由本轮核实。
7. OCR 来源由客户端记录，服务端核对归属、字段及版本，但它不是对原图内容的密码学证明；所有识别内容须对照实物核对。
8. 单药逐图资料限 100 张、单图 32 KiB、整份 256 KiB；来源保存回执每家庭限 8192 条。超限明确拒绝，不删除旧资料，但需要后续容量治理。Release 编译出现 Cupertino 图标字体提示，安卓实际页面是否受影响尚待设备检查。
