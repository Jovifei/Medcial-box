# 家庭药箱：用户路径与页面层级审核

## 结论

现有四个主导航方向合理，添加药品已集中在一个表单页，选填说明书收起、识别失败仍能填写、药品草稿退出保护值得保留。优化重点是**减少首屏选择、重复入口和设置错位**。常规添加只使用一个业务页，不新增搜索页、候选详情页或分步向导。

## 主要体验问题

| 编号 | 发现 | 对用户的影响 | 优化 |
|---|---|---|---|
| U01 高 | 首屏药名后依次用途分类、人群、九个用途标签；余量/日期更下方（截图2） | 用户以为都要填写，看不到录入最重要的信息 | 药名→余量＋单位→包装有效期；人群/用途/位置默认折叠为“分类与位置” |
| U02 高 | 保存按钮位于首屏下方约1088逻辑像素（截图2/3及offset） | 只填药名也要找保存、滚动 | 固定底部“保存药品”，键盘弹出仍可达，正文留足底部空间 |
| U03 高 | custom-nav为position:relative，滚动后消失（截图3、medicine-edit.wxss） | 返回控件不在场，内容与状态栏/胶囊相撞 | 固定安全区标题栏，内容顶部留高度；标准导航可用则优先复用 |
| U04 高 | 用途分类和用途标签并列；更多资料里还有自由用途分类（截图2及WXML） | 不知道哪个生效，重复填写 | 只显示一组“用途”多选；旧自由文本在更多资料保留，不能迁移时丢失 |
| U05 中 | 首页先选来源，进录入页又展示完整拍照/相册/扫码大按钮（源码index.ts） | 重复选择感，识别后输入被操作区挤下去 | 建议加号直接进入添加页；选择来源后顶部收为照片预览＋重新拍/补拍，不重复大菜单 |
| U06 中 | 第一份也叫“批次1”，默认显示删除和“加一批次”（截图3） | 普通家人不懂批次，担心误删整种药 | 初次显示“这份药的库存”；“另有同款药？再加一份库存”放次级，删除放该份更多菜单 |
| U07 中 | 用“大开关”选择数量未知，打开后数量输入消失（截图3） | 填数量先关开关，多一步且难理解 | 数量可留空，提示“留空表示未知”；0表示已用完，单位与数量同一行 |
| U08 中 | 有效期先选精度再手填YYYY-MM-DD（源码） | 用户要理解格式且容易输错 | 点击日期行打开短选择面板：具体日期/只有年月/未填写，尽量点选；始终保留印刷精度 |
| U09 高 | 我的顶部家庭按钮与下方“我的家庭/邀请”重复；退出登录/显示名在邀请页（源码mine/invite） | 账号操作不好找，邀请页承担无关管理 | 我的显示一条家庭入口；退出与显示名属于账号设置，成员/邀请/转让/退出家庭集中“我的家庭” |
| U10 中 | 家庭设置有成员只读列表，真正成员管理在邀请页（源码family-settings/invite） | 进入家庭却不能就近管理，要猜下一页 | 家庭页成员行直接管理；邀请仅生成/分享邀请，不混个人设置 |
| U11 中 | 详情有“说明书摘要”卡，随后“说明书与来源”又显示同样摘要；新增库存/更多操作多处重复（源码detail.wxml） | 长页面反复看同一信息，常用按钮不集中 | 顶部身份＋库存操作；说明书合为一组；归档/删除收进更多，修改余量就近放库存行 |
| U12 中 | 首页状态一排，成人/儿童/九用途/排序又一长横排（源码index.wxml） | 分类维度混在一起，排序需横向寻找 | 常驻“用途、人群、状态、排序”四入口，已选条件另显示，选择用底部面板 |
| U13 高 | 当前登录只显示请求失败401（截图1）；启动页为login且该页无有效会话恢复路由（源码app.json/login.ts） | 不知道如何恢复；默认启动路径有重复登录门槛 | 有效会话直接药箱，无会话才引导；错误写清重试措施，不给HTTP编号当解释 |

当前药品保存后回原页面的行为，在“降低添加跳转”目标下适合保留。先前方案约定的新建后强制进详情，建议调整为回药箱定位记录，详情由用户选择。

## 一级、二级、三级交互的职责

| 层级 | 应放什么 | 不应承担什么 |
|---|---|---|
| 一级：四个主导航 | 药箱、用药计划、待处理、我的；用户的四类任务 | 大功能九宫格、管理员操作、冗长设置 |
| 二级：任务页面 | 添加药品、药品详情、创建/编辑计划、我的家庭、数据导出、账号设置 | 只改单位/余量也跳完整表单，或者再建中转页 |
| 三级：短选择/确认 | 单位、日期、人群/用途、改余量、位置、共享权限、危险操作确认 | 长说明书、多字段创建表单、深层嵌套弹窗 |

三级通常是停留在当前页的面板，不等于第三个路由页。长内容仍使用可返回的页面，例如说明书原文、备份预览。常规添加不需要第三个业务页面。

## 建议的最短录入路径

```text
药箱 → ＋添加 → 一个添加页 → 保存 → 回药箱定位刚新增记录
                         ├ 拍药盒/扫码：系统操作完成后回同一页
                         ├ 识别/资料候选：同页核对，不进另一个详情页
                         └ 日期/单位/分类：短面板选择后仍在同页
```

手动录入只需“打开添加、填药名、保存”，名称仍唯一必填。拍照路径保留用户核对这一步，不把省操作变成自动入库。默认数量/日期留空，不自动填写“0”或今天。

### 添加页建议布局

```text
固定标题：‹ 添加药品
拍药盒     扫药码      相册（次级）
［选中的照片＋识别/核对状态］  ← 有照片才占空间
药品名称 *
剩余数量（可空）      单位 ▾
包装有效期（可空）          ›
分类与位置                 ›  默认收起
开封信息                   ›  默认收起
更多药品资料与说明书        ›  默认收起
固定底部：保存药品
```

- 分类展开才出现人群、用途、存放位置；识别已给标签时折叠摘要可显示“儿童·咳嗽·客厅”，并标核对状态。
- 多候选时只展开必要的厂家/规格区分，按钮写“使用这条资料”；“候选”“填入空字段”等实现术语不作为主要操作文案。
- 识别失败留在本页，输入和保存可继续；不要送往错误页或要求重新开始。
- 有同名药才出现“添加新库存／另建药品”选择，不强制去搜药→详情→批次编辑。
- 默认不显示多批次、包装換算、低库存设置、用药计划、家人剂量；这些在保存后的详情按需管理。
- 保存回首页后轻量显示“已添加”，定位并突出记录；提供可选“再添加/查看”，不强制新页面。新记录不符合原筛选时提示“已保存，当前筛选未显示”，可查看，不默默清掉所有筛选。
- 从已有药品详情编辑/增加库存，保存回该详情并刷新；从待处理改数量，返回待处理。取消回原入口，草稿不丢，不自动重放写请求。

来源面板并非一定不好：若以后数据表明大多数用户喜欢首页快捷选来源，也可保留，但不要同时在后续页重复大入口。本次推荐默认直接单页，尤其减少手动录入额外选择。

## 登录和家庭引导

1. 有效会话且已有家庭：直接药箱；不反复让用户登录。
2. 未登录：登录引导只在需要真实保存/共享前出现；游客只看介绍/明确示例。不要填到最后才告知需要登录。
3. 登录后无家庭：“创建自己的药箱／加入家人的药箱”在同一处选择。创建用短面板，提供默认名称“我的药箱”，用户确认后才创建。
4. 邀请链接：登录后回目标家庭预览，只保留一次最终“确认加入”；不再先绕创建家庭。
5. 网络/登录失败：解释当前没完成、能否重试，保留来源和草稿；不要只显示401。退出登录在账号设置，退出家庭在家庭设置，两个影响说清楚。

## 其他页面位置建议

- 药品详情：药名/照片→库存→“改余量、开封、增加库存”→用途摘要；说明书、低库存、备注收起；归档/删除/历史收进更多。
- 药箱首页：家庭名、搜索、紧凑状态、四个筛选入口、列表、添加；保留列表位置。搜索框清除只清关键词，筛选重置独立，不能一次点击意外丢全部条件。
- 待处理：每项直接进入对应短操作，不要求先找药品再找批次再编辑。
- 我的：首页只保留家庭/用药的人、提醒、数据、账号四组入口；已登录设备缩成一行计数，登录和到期时间进入设备详情再看。
- 家庭成员（登录账号）与用药的人（我/孩子/老人）视觉文案分清，不能让用户误以为孩子必须注册微信或邀请加入。
- 用药计划：今天为默认，查看全部为页内切换；创建长表单用独立页面，避免长底部面板被键盘盖住。选择家人就近面板，不绕“我的”。

## 优化顺序及验收

- 第一批：固定添加页顶部/底部，重排基本字段，合并用途，空数量代表未知，收起分类与多库存；同页识别失败恢复。
- 第二批：收口家庭/邀请/账号入口，移出重复菜单；短数量/日期设置就近完成；详情去重。
- 第三批：有效会话恢复与原操作返回、首页筛选位置、计划长表单和草稿；与已发现的技术跳转/并发缺陷一起回归。

验收以具体任务为准：名称-only保存不找第二页；拍照后不离开核对页；补有效期只开一个面板；改余量不进入全资料表单；返回保留搜索/滚动；单位/日期取消不改值；首次登录回原操作；无修改返回不确认，有修改提供继续/保留/放弃；390及320宽、大字体、键盘、系统返回检查不遮字/按钮。

不以机械“少点几下”删除核对、共享同意、删除/退出确认。只有首次登录/建家庭、明确授权、多个匹配或危险操作等有理由时才增加确认。本轮未实现以上建议、未完成真实保存和登录链路验收；截图仅支持已实查页面的布局结论。
