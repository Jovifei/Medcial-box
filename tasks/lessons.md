# 实施经验记录

本文件仅在项目实施中出现明确纠错或反复验证后追加经验。

## 2026-09-23／24

- Windows 上 npm 首次下载 Biome 原生二进制（约 76 MB）不可靠：lint 链路改用 TypeScript ESLint 加 JSON 语法检查，并从依赖中移除 Biome（详见 tasks/plans/2026-09-23-p0-project-bootstrap.md）。
- 本机 Docker CLI 29.7.2 未安装 `docker compose` 插件，只有独立版 `docker-compose` v5.4.0：文档、验收证据与脚本统一使用 `docker-compose`，避免"照 README 抄命令即失败"。
- 连接池环境下 `pool.query("BEGIN") … pool.query("COMMIT")` 不构成事务：每条语句可能落在不同连接，部分写入不会回滚。多步写入必须走 `Database.withTransaction`（绑定单个 PoolClient）；合成假池的 withTransaction 同步包裹脚本执行并记录 BEGIN/…/COMMIT 顺序，真实并发场景由 `integration-pg.test.mjs`（设 `TEST_DATABASE_URL` 自动执行）覆盖。
- 迁移执行入口必须唯一：Postgres `/docker-entrypoint-initdb.d` 只跑 SQL 不登记 `schema_migrations`，与迁移器并用会导致二次建表失败。容器化部署只让 API 迁移器跑迁移。
- 涉及"父记录 + 子记录"的并发：子记录端点必须递增父记录聚合版本（批次增/改/删 → 药品 version + 1），否则旧页面的整体保存会绕过乐观锁静默覆盖/删除他人新增的子记录。
- 单 owner 这类"恰好一个"不变量，唯一索引只能保证"最多一个"——转让/退出/移除必须共用同一把家庭行锁并在事务内复核角色，删除/降级语句要带角色条件。
- 业务"今天"绝不能取 UTC 日期部件：家庭时区固定 Asia/Shanghai（`zonedDateParts`），否则中国时区凌晨 0–8 点之间到期日会整体偏移一天。
- 异步界面：开关/筛选变化后，旧请求的响应必须作废（请求序号 + 选项快照比对），复制/分享等动作前按当前选项重新生成，防止"看到的与拿到的"不一致。

## 2026-09-27

- 交互原型的按钮不能只改变页面文案：备注、批次、归档和导出开关都要有可读取的数据状态，Widget 测试至少检查仓库写回或预览内容变化；页面底部控件的测试要使用可滚动的小屏/大屏边界，避免只测到存在而没测到可点击。
- 小程序网络方法要按微信运行时实测兼容性设计：保留后端 PATCH 契约的同时，为客户端提供 POST 兼容入口，并在导入包测试中锁定方法与路径，避免页面只显示笼统的“请求格式不正确”。

- 新增登录／家庭入口时，邀请码必须作为导航状态的一部分保存：会话过期、重新登录和预览 401 都要把邀请码重新带回登录页；代理后的限流应优先按已认证 user_id，客户端地址只用于匿名登录且由受控反向代理覆盖转发头。

- 复制／分享的系统调用发出后无法撤回：调用前继续允许更改导出选项并作废旧请求；调用发出至完成期间锁定选项和页面重新加载，避免界面显示的选项与已交付内容不一致。测试既要检查提示，也要检查是否实际调用了剪贴板／分享接口。
- 写入临时导出文件可能在失败时留下部分内容：路径必须在写入前纳入清理队列，删除必须等待成功回调；失败要告知用户，并在下次进入页面重试。只断言 `unlink` 被调用不足以证明敏感文件已经删除。
- 临时数据库进程可能在工具会话切换后停止。真实数据库复跑先做就绪检查；遇到 `ECONNREFUSED` 先排除运行环境，再报告最终严格模式测试结果，同时保留首次失败证据。
- 配置沟通须分清来源：`POSTGRES_PASSWORD` 是项目独立数据库的新密码，`WECHAT_APP_ID` 是公开标识，只有 `WECHAT_APP_SECRET` 是微信提供的那一个密钥。创建忽略文件并生成数据库密码后，只让 Jovi 填入微信密钥，不再笼统要求填写“三个密钥”。
- 运行环境状态会变化：上一轮 Docker Desktop 起不来，本轮先重新执行 `docker info`，确认引擎已就绪后再处理镜像和 Compose；不要把旧阻塞延续为当前结论。
- 用户指出录入字段多时，先看默认交互的真实阻力：虽然规格、厂家等在 API 层可选，但页面全量展开、批次数量默认空且要求填写，仍会让首次录入显得必须填长表。先把最少必填和可点选项摆到前面，选填资料收起，再接识别草稿；不要用“字段其实可选”代替改界面。
- Windows PowerShell 调用 `node -e` 写私有 `.env` 时，嵌套转义曾把换行写成字面 `\\n`，导致模型配置未生效。不要打印密钥排查；只检查键名与配置存在性，使用明确的换行字符构造文件，并在重建容器前跑 `config --quiet`。
- 图片识别页面必须有持久化状态面板：这次设备日志证明请求已到 API，但 Ollama 因异常图片数据返回 503，单靠 Toast 会让用户误以为没有反应。识别失败要在表单内显示原因和手工录入路径；后端还要在调用模型前检查图片结束标记，避免把截断图片送入本地模型。

## 2026-10-03 收尾复核

- 单页录入不仅减少跳转，也要保护失败后的状态：请求结果不确定时冻结原提交内容及幂等键，先确认原结果，再允许修改已保存记录；照片补传不能把后续编辑悄悄丢弃。
- 官方小程序样式编译应一次传入完整依赖；逐文件调用会误报 import 缺失。真实编译仍发现邀请页标签闭合问题，不能用 TypeScript 通过替代 WXML 编译。
- 包装换算必须保存目标单位；瓶到毫升按目标精度验证，更新省略目标时继承已确认关系。SQL CHECK 遇 NULL 应显式处理，不能依赖三值逻辑保证整数。
- PNG 照片不能只重命名为 JPG 并宣称 JPEG；持久化与上传必须保持真实图片格式。
- 部署说明要分清服务域名、ECS IP、SSH用户名和DNS权威方。DNS截图若显示第三方权威NS，就必须先在该处加记录，或完整迁移所有现存记录后再切换到用户选择的权威DNS；不能因ECS在阿里云就推断DNS必须在阿里云。

- 部署沟通必须分清域名、服务器IP、SSH别名与Linux用户：medbox-test是服务域名，etfdeploy是先前提供的服务器登录用户，不能把登录用户描述为药箱绑定。DNS应按实际权威NS解释，与ECS供应商独立。

## 2026-10-03 OCR 与日期控件复核

- 依赖系统本地化的日期/滚轮控件不能只配中文页面文案；Flutter 根节点要提供 `zh_CN` 与 Cupertino/Material localization delegates，显示中文年月日，提交值继续用 ISO 日期。
- 小程序草稿保存 `unitIndex` 时，单位列表只能在末尾追加或显式迁移旧草稿；插入中间会把旧索引解释成另一种数量单位。
- OCR 药名取表单词命中位置之前的候选文本，截断后缀英语和尾随噪声；回归要覆盖真实药名、混排标签和误识别尾字符。

- 日期选择不能只修首次录入页：新增/编辑批次、开封和截止日期须复用同一组件；底部面板校验不能使用被面板遮住的SnackBar。库存资料应原位修改，不要求用户复制或新增批次。

- 编译前fetch并逐个核对远端分支SHA/祖先关系；“本地主分支已同步”不代表最新开发分支也已包含。另一AI持续提交时明确本次冻结源点，不能只看提交数量。
- Jovi要求先独立试用App时，不再把小程序连接码作为前置；仅通过显式本机测试构建接入测试身份，正式连接流程保留。

- 用户指出IDE仍旧时，必须核对实际打开目录并刷新实际项目；源码测试和wcc/wcsc通过不能替代IDE编译和模拟器检查。交付记录明确小程序导入路径/源SHA与App APK。

- 交付小程序不得以wcc/wcsc或mock wx.login的结果称整包编译/手动登录/真机通过。必须核对用户实际项目目录和API配置，检查代码质量、sitemap及预览上传；多项目工具中不能只验证另外一个隔离项目。

- 真机微信出现域名校验拒绝时，不能归因API未启动；电脑urlCheck本地设置不等同手机开发调试状态。预览上传成功只证明包通过，手机扫码进入和登录须实际另验。

## 2026-10-04 最新分支与验证

- 较晚的审计分支不一定包含另一审计分支的修复；先比较祖先与逐文件差异，再回补缺项，保留两边有效改动。
- 新分支前缀必须核对 workflow push 过滤器；没有精确 SHA 运行就是未验证，不能沿用 main 的绿灯。
- 诊断日志同样可能泄漏令牌：用户文案非技术化后，后台也只保留白名单类别，不把原始错误串/URL直接写入日志。

- 草稿存储按家庭分键不等于整条异步流程安全：选图/读文件/登录/上传之后，要再次核对原账号及家庭；旧弹窗确认不得用于新身份下的同ID对象。已发出请求不可撤销与禁止后续串家庭操作需要分别说明。
- 为 APK 减包移除字体声明后，宿主图像/PDF测试应显式读取仓库fixture；不要以删除测试或把10 MB重新打包来掩盖缺资源。启动时注册的许可证仍须可读取。

- 删除本机照片不能只凭 USER_DATA_PATH 前缀：精确路径、草稿及家庭归属必须一致；删除前先持久化清理意图，失败保留记录。无法证明归属的旧文件保留，不能把“调用过unlink”当作已删除。
