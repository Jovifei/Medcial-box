## P1 核心闭环：手动药箱＋Markdown 导出

1. 新增迁移 `002_core_inventory.sql`：用户、家庭、成员、哈希会话、药品、库存批次和个人剂量备注。首次登录只创建用户；在进入药箱前由用户调用 `POST /api/v1/families` 创建家庭并成为 owner。P2 加入邀请入口，因此受邀用户登录后不会被自动塞入一个个人家庭。首版每个账号只加入一个家庭。每条药品／批次有 `family_id` 或由外键绑定家庭、创建／修改人、修改时间和整数版本。
2. 服务端实现 `POST /api/v1/auth/wechat`：小程序 `wx.login` 的临时 code 只交服务端交换 openid；发放随机会话令牌，数据库仅保存令牌哈希与过期时间。实际 AppID／AppSecret 仅由服务端环境读取；自动化测试注入假的微信网关，不提供公开的“测试登录”接口。
3. 实现药品与批次的列表、详情、新建、编辑、归档 API，并在每个读写端点核对家庭成员身份。更新请求携带记录版本；版本不符返回 HTTP 409。药品身份与批次分开；批次数量 `null` 表示未知、`0` 表示确定耗尽，盒内片／袋数只有经用户确认后才用于换算。
4. 有效期保存原文与精度：`YYYY-MM-DD`、`YYYY-MM`、未知。年月只显示月份；过了该月才标为过期，该月内标“本月到期”，不伪造日期。精确到日的记录默认提前 30 天提示临期。库存有药不表示适合某人服用。
5. 实现小程序药箱首页、手动录入／编辑、批次详情与导出预览。说明书摘要可手填，显示来源与核验状态；用户对照包装内说明书后可显式标为“本人已核对”，未核验的用法信息不在默认导出中冒充已确认资料。实际每日剂量作为独立的成员备注，不从药品名称或通用说明生成。
6. `POST /api/v1/exports/markdown` 默认导出全量库存的分区清单、批次、有效期精度、已确认的说明书用途／用法／禁忌摘要及来源；未知、零库存、过期显式标注。请求中的 `includePersonalDosage` 默认为 `false`，勾选时只包含当前用户有权查看的备注。返回 UTF-8 Markdown；小程序预览后写本地 `.md` 再调用 `wx.shareFileMessage`，并始终提供复制文本。
7. 验收：真实 PostgreSQL 验证迁移与增删改查；合成测试覆盖无家庭会话、跨家庭拒绝、过期算法、同药多批次、未知与零、409 冲突、导出字段及 Markdown 转义。首批功能代码就绪后，先核查可用的 AppID／HTTPS 域名和现有服务器，在独立测试环境验证真实微信登录、手动库存和 `.md` 真机分享；环境缺失时只标 `PASS_CODE_ONLY`，不以测试替代真实使用。

## P2 家庭共享

1. 家庭 owner 生成一次性邀请凭据，服务端只存哈希，72 小时失效；被邀请人先用自己的微信身份登录，再从邀请入口加入。已有家庭成员关系的用户不得直接加入第二个家庭；界面说明需先处理原家庭，不自动搬移或合并药品。首版所有成员可维护共享药品，只有 owner 管理邀请和移除成员。
2. 每次读写按服务端会话查询家庭成员关系；移除成员后立即失去访问权限。个人剂量备注默认仅备注所属成员可见，主动选择“全家可见”后其他成员才能阅读；Markdown 导出遵守相同权限。
3. 并发编辑通过版本号产生 409，让用户查看最新值后重新提交，不静默覆盖。
4. 验收：邀请过期／复用、跨家庭请求、成员移除、备注可见性和并发冲突自动测试；真实两账号共享验证须在合法 HTTPS 测试环境可用后进行，没有实测不标完整 PASS。

## P3 拍照识别与药品资料补齐

1. 用户拍药盒／有效期或说明书后，照片经鉴权上传到私有目录。服务端创建识别草稿：识别候选、原始字段、来源、匹配依据、状态与失效时间；草稿与正式库存分开，用户确认后才入库。
2. 阿里云百炼视觉模型和极速数据查询通过独立适配器接入，密钥留在后端。批准文号优先，结合厂家与规格确认；同名、模糊或冲突只展示候选，不自动套用说明书或个人剂量。处方药说明书缺失、服务故障或无匹配时保持手动录入／补拍路径。
3. 已确认记录保留照片私有访问入口、资料来源和核验状态；临时草稿照片按 24 小时过期清理，正式照片随用户删除／备份策略管理。
4. 验收：合成图片与假适配器覆盖清晰／模糊、无匹配、字段缺失和服务失败；得到专用账号与用户明确选定的药盒后，另记录真实识别准确率、错误和人工修正。合成测试不算提供商 PASS。

## P4 上线准备与家庭试用

1. 复核 P1 开始使用的隔离 HTTPS 测试环境；准备正式部署配置、真实小程序 AppID、合法请求／上传／下载域名和服务端密钥。生产容器不能使用开发默认密码。
2. 为 PostgreSQL 与私有照片建立持久卷、备份计划及隔离环境恢复演练；补充隐私说明、成员退出／数据删除路径、日志敏感字段处理、依赖／镜像版本记录，并监控健康检查、存储空间和备份失败。
3. 先用测试环境完成两个家庭成员的邀请、录入、并发修改、拍照核对与 `.md` 真机分享；随后再评估正式发布。真实微信、提供商、备份恢复和服务器运行分别记录证据，不由 HTTP 200 或合成测试推断。

## 后续功能候选（首版验收后再排期）

- 高优先级：低库存阈值、临期／过期的微信订阅提醒、批量盘点及完整备份导出。
- 中优先级：条码辅助检索、服药计划与确认记录、个人用药历史。若加入自动扣库存，先建立明确的确认和撤销机制。
- 暂缓：小程序内直接向 AI 问药／推荐用药。先验证外部 AI 清单的实际使用价值，再决定是否引入新的医疗与隐私责任。
