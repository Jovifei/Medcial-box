# 药品录入改为拍照优先

Jovi 在本地试用时指出：录入页把大量非必填资料铺在主流程，实际用户难以逐项输入。原 P3 拍照识别前移到本地试用阶段；本地 Docker、真实微信登录及家庭创建已通过，当前暂停要求用户继续手工填长表。

## 交互与边界

1. 首屏主入口为拍药盒或从相册选择图片，服务端识别后返回**草稿**。识别不创建库存；用户查看并修正后再点保存。
2. 第二层是可点选的单位、日期精度、用途分类等常用项；最少手填仅为药品名称。数量默认未知、有效期默认未知，既不把空数量写成零，也不推断有效期日。
3. 规格、厂家、批准文号、成分和说明书放入可展开的“补充信息”；其值仍可手工填写或由照片预填。照片看不到的字段保留空，不生成个人用药方案。
4. 识别图片只经认证 API 传给服务端，服务端仅返回结构化草稿，本轮不持久化原图。本地优先使用现有 RTX 4070 SUPER 上已验证的 Ollama `qwen3.5:0.8b`；百炼保留为远端可选适配器。模型密钥仅在需要云端时由服务端保存。失败可继续点选或手填。

## 接口契约

`POST /api/v1/recognitions/medicine`，Bearer 鉴权，JSON `{ imageBase64, mimeType }`（只接受 JPEG/PNG，限制大小）。返回 `{ draft, warnings, requiresConfirmation: true }`，其中 `draft` 仅包含照片中有证据的 `name`、`specification`、`manufacturer`、`approvalNumber`、`purposeCategory`、`lotNumber`、`expiryValue` 和 `expiryPrecision`；无法确定时为 `null`。库存数量不从照片推断。百炼密钥未配置时返回明确的不可用错误，前端保留快速手工路径。
