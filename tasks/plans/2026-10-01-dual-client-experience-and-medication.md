# 2026-10-01 双端录入体验与用药计划实施方案

## 一、目标与交付顺序

本阶段同步完善**微信小程序和 Android App**，围绕三个主要任务设计：**快速录入家里的药、找到需要查看的库存、记录并提醒已有用药计划**。

已确认的选择：

- 米白背景、深绿主色，配合青绿图标和轻量底部面板。
- 最近一轮交付录入、筛选、提醒、登录引导、版本更新及用药计划。
- 本人用药计划默认私有；孩子、老人由创建者管理，可指定照护家人。
- 提醒后支持"已服用／本次跳过／未确认"，保留历史，暂不自动扣库存。
- 联网关键词搜药、药箱分析、就诊档案和健康统计纳入后续路线。

当前候选代码已有库存、开封管理、扫码候选、图片识别、家庭共享和到期提醒基础，但缺少完整的药盒照片展示、人群标签、多条件筛选、服药计划和更新提示。当前工作树还有正在进行的未提交修复，实施开始时先复核这些改动及验收结果。

**优先级固定为：数据正确性 → 录入和查找 → 用药计划 → 真实通知 → 后续分析。** 上一轮审核中的恢复、身份隔离、误写和提醒问题先完成回归，随后增加新功能。

## 二、页面布局、视觉与页面跳转

### 1. 四个底部导航

统一为：

| 导航 | 主要内容 | 图标 |
|---|---|---|
| 药箱 | 家庭库存、搜索筛选、录入 | 药箱轮廓 |
| 用药计划 | 今日安排、计划管理、服用记录 | 日历＋时钟 |
| 待处理 | 过期、临期、低库存、盘点、资料缺失 | 清单＋提醒标记 |
| 我的 | 家庭、照护对象、提醒设置、导出、设备和版本 | 人物轮廓 |

首次登录后默认进入"药箱"。切换导航保留各页面的搜索、筛选、日期和滚动位置；从通知进入指定页面时，返回能够回到对应导航。

联网"搜药"以后作为录入面板和药箱搜索页里的入口，不新增一个底部导航。

### 2. 视觉规范

| 元素 | 规范 |
|---|---|
| 页面背景 | 米白 `#F5F7F4` |
| 卡片 | 白色，圆角 16，轻边框，减少大面积阴影 |
| 主按钮、选中导航 | 深绿 `#3F7D5C` |
| 扫码、相机、家庭等功能图标 | 青绿 `#268C86` |
| 正文 | 深色 `#24382E` |
| 次要文字 | 灰绿 `#596A60` |
| 成人整理标签 | 蓝色文字＋浅蓝底 |
| 儿童整理标签 | 绿色文字＋浅绿底 |
| 用途标签 | 紫色文字＋浅紫底 |
| 临期、低库存 | 深橙文字＋浅橙底 |
| 已过期、删除操作 | 深红文字＋浅红底 |
| 未知、待核对 | 灰色文字＋浅灰底 |

状态始终同时显示文字，不能仅靠颜色区分。图标使用同一套线性风格；App 使用 Material 图标，小程序使用项目内对应资源，替换目前不一致的 Emoji。

- 页面左右边距 16，卡片间距 12。
- 标题 20–24，正文 16，辅助文字 13–14。
- 输入框、主要操作区域高度至少 48。
- 导航图标 24，列表功能图标 22–24。
- 页面过渡约 220ms，底部面板约 240ms；系统减少动画时简化。
- 覆盖 320–430 宽度和大字体。标签换行，长药名允许两行。
- 所有底部按钮避开导航、安全区和键盘；不覆盖最后一张药品卡。

### 3. 药箱首页

从上到下排列：

1. 家庭名称，右侧"我的家庭"。
2. 搜索框：提示"搜索家里的药名、厂家、成分或位置"。
3. 紧凑状态摘要："在管药品、临期／过期、库存不足"。
4. 筛选行："用途、人群、状态、排序"。
5. 药品列表。
6. 右下角"＋录入"按钮。

不增加独立的功能九宫格首页，让用户打开后直接看到家里的药。

**药品卡片布局：**

- 左侧 64×64 药盒缩略图；没有照片显示药品占位图标。
- 第一行：药名，最多两行。
- 第二行：人群标签、用途标签，最多显示三个，其余显示"＋N"。
- 第三行：余量和最早管理截止日期。
- 第四行：选填位置、简短备注；无内容不占高度。
- 多批次显示"共 N 个库存记录"，进入详情查看全部日期和余量。

小屏幕采用上下排列，避免药名、日期和标签挤在同一行。库存问题与历史批次分开展示，不能把已处理批次继续算进现有余量。

**筛选与排序：**

- 用途、人群支持多选；不同维度同时满足，同一维度任选匹配。
- 状态包含正常、临期、已过期、库存不足、已耗尽、待核对、已归档。
- 默认展示未归档药品，默认按最早管理截止日期升序。
- 支持到期升序／降序、名称、最近录入排序。
- 未知日期置末；同日用稳定次序排列。
- 返回首页保留条件；"清除筛选"恢复默认。
- 真正空药箱显示"录入第一种药"；筛选无结果显示"没有匹配结果"。

### 4. 录入与核对页

点击"＋录入"打开底部面板：

- 第一排两个突出操作：**扫药码、拍药盒**。
- 第二排：从相册选择、手动录入。
- 后续增加：联网搜药。
- 支持连续采集最多 10 份草稿，逐份核对保存。

页面流程：

```text
药箱 → 录入面板 → 扫码／拍照／相册
     → 候选或识别草稿 → 核对页 → 保存 → 药品详情

手动录入 → 同一核对页
识别失败／扫码无结果 → 保留已有内容 → 手动补填
```

**核对页分组：**

1. 图片缩略图、识别状态、补拍／重新选择。
2. 药品名称——唯一必填项。
3. 余量、单位、包装有效期。
4. 人群和用途标签，可跳过。
5. 存放位置，可跳过。
6. "已经开封？"展开已有开封日期和期限设置。
7. "更多资料"折叠厂家、规格、批准文号、成分和说明书。
8. 底部固定"核对后保存"。

扫描和识别均只生成草稿。日期未知仍可保存；不自动生成有效期。重新识别采用字段差异核对，不覆盖用户已经修改或明确清空的字段。

同名药已有库存时展示"添加到已有药品／新建药品"，由用户选择；厂家、规格不同不能自动合并。

### 5. 药品详情

布局顺序：

1. 药盒照片、药名、规格。
2. 人群和用途整理标签。
3. 当前库存记录：余量、包装有效期、开封截止日期、存放位置。
4. 快捷操作："修改余量、标记开封、新增库存"。
5. "创建用药计划"入口。
6. 折叠区域：说明书与来源、个人备注、低库存设置。
7. 更多菜单：历史库存、归档、删除、变更记录。

药盒正面照片用于识别药品；有效期照片绑定具体库存记录。说明书图片单独展示，不能自动充当药盒封面。

点击"创建用药计划"只带入药品身份，剂量和时间由用户填写。

### 6. 用药计划

采用"今日安排／全部计划"两个页内视图。

**今日安排：**

- 顶部日期及左右切换，不默认展示复杂月历。
- 照护对象选择："我、孩子、老人或已授权家人"。
- 按时间排列提醒卡片。
- 每项展示时间、药名、手填剂量、备注和确认状态。
- 操作："已服用、跳过"；确认后可进入详情纠正。
- 超过时间但没有记录，显示"未确认"，不直接判定漏服。
- 页底"＋创建计划"。

**全部计划：**

- 进行中、暂停、已结束筛选。
- 卡片展示照护对象、药品、时间点及起止日期。
- 点击进入计划详情，查看历史记录、编辑、暂停或结束。

**创建计划页：**

1. 选择照护对象。
2. 从药箱选择药品，或手填药名。
3. 填写剂量文字；结构化剂量可选。
4. 选择每天或指定星期。
5. 添加每日时间点。
6. 起始日期、选填结束日期。
7. 选择有权限的照护人及提醒接收人。
8. 保存后单独设置通知授权。

第一版支持固定时间安排，不做自动推导剂量、复杂递减方案或按需服药调度。暂停或结束只取消未来安排，保留历史。

### 7. 待处理与"我的"

**待处理**按以下顺序展示：

已过期／开封期限已到 → 临期 → 库存不足 → 盘点到期 → 待补资料。

每项带直接操作，如修改余量、补日期、加入补货清单、记录已处理。服药确认统一放"用药计划"，不混入库存问题清单。

**我的**按四组排列：

- 家庭与照护：我的家庭、照护对象、共享权限。
- 提醒与设备：提醒设置、连接 App、已登录设备。
- 数据管理：补货清单、导出、备份恢复、最近删除、变更记录。
- 应用信息：版本与更新、使用帮助、隐私说明、退出登录。

"就诊档案、健康统计、药箱分析"在后续交付后再显示正式入口。本阶段不放不能使用的按钮。

### 8. 登录与更新引导

欢迎页提供"微信登录"和"先了解"。游客只能查看产品介绍及明确标注的示例，不能访问真实家庭数据。

受保护操作触发登录面板，说明当前操作的用途。登录后：

```text
有家庭 → 返回原操作
无家庭 → 创建家庭／加入家庭 → 返回原操作
邀请进入 → 登录 → 邀请预览 → 确认加入
```

App 继续通过小程序确认连接码授权，同步提供"先了解"。不要求头像、手机号或生日才能进入药箱。

更新分两类：

- **功能介绍**：新版本首次进入显示最多三项重点改进，每个版本仅提示一次；"我的→版本与更新"可再次查看。
- **安装更新**：小程序在新版本准备就绪后提示重启；先处理未保存草稿，再执行更新。App 本阶段使用受控 APK 发布入口，用户确认安装，不做静默覆盖。小程序 `applyUpdate` 会重启应用。[微信更新接口](https://developers.weixin.qq.com/miniprogram/dev/api/base/update/UpdateManager.applyUpdate.html)

## 三、功能规则、数据和接口

### 1. 余量、单位与照片

新增 `ml`（毫升）和 `blister`（板），保留片、粒、袋、瓶、盒及其他。

- 毫升支持最多三位小数；计件单位使用非负整数。
- 未知数量用空值，零表示已经没有。
- 单位切换不自动解释或换算旧数字，保存前要求确认。
- "一板几片""一盒几板""一瓶多少毫升"必须由用户确认。
- 未确认换算时，展示"2 板＋3 片"等分组余量，不强行相加。
- 包装容量不等于实际剩余量；不会因为识别到"100ml"就自动填写剩余 100ml。

当前整数数量链路须统一升级：数据库采用定点数量，服务端定点运算；同步修改两端模型、阈值、盘点、拆分、补货、导出和备份。新增迁移，不修改已执行迁移。

照片复用现有私有存储、家庭鉴权、配额和清理机制，新增包装图片用途与封面引用。保存库存和照片关联失败时明确告知结果，不能让用户误认为照片已保存。

JSON 库存备份升级版本并兼容旧版；图片文件仍通过独立图片备份恢复。旧客户端不能读取新单位时提示更新，禁止默默转换成"其他"。

### 2. 标签与搜索

新增可多选的人群整理标签和用途标签：

- 人群：成人、儿童、未标注；允许成人和儿童同时标记。
- 用途：发热、咳嗽、咽喉、鼻部、胃肠、疼痛、外用、过敏及其他。
- 保留旧用途字段的兼容读取；已有自由文本不能迁移丢失。
- 标签属于家庭整理信息，记录人工填写或资料来源；不能据此宣称药品适合某个人。
- 说明书年龄限制、禁忌和核对状态在详情独立展示。

药箱内搜索本阶段完成；联网搜索结果页后续完成。扫码仍复用现有资料候选接口，区分商品码、追溯码和普通二维码；普通网址不自动打开，无可用数据源时保留码值并引导拍药盒。

### 3. 账号、照护对象和计划权限

明确分开：

- 登录账号：谁在操作。
- 家庭成员：谁有库存权限。
- 照护对象：谁的用药计划，可关联账号，也可为无需登录的孩子或老人。

新增照护对象、授权关系、计划、计划时间点、服药实例、确认事件和通知投递记录。

默认规则：

- 本人计划仅本人可见。
- 孩子、老人由创建者管理，其他家人通过明确授权获得查看或管理权限。
- 接收提醒与编辑计划分别配置。
- 家庭管理员身份不自动获得私有计划。
- 移除家庭成员同时撤销其照护权限和未来服务端通知。
- 修改计划只改变未来实例；既有服药记录保留当时计划信息。
- 多人同时确认同一次服药，只产生一次有效状态；纠正保留操作记录。
- 服药记录不自动扣减库存。

本轮库存导出和家庭 JSON 备份不包含私有照护计划。后续提供按权限单独导出健康记录。

### 4. 接口扩展

继续采用 `/api/v1`，最小增加：

| 接口组 | 用途 |
|---|---|
| 药品、库存接口增量字段 | 标签、小数毫升、包装换算、封面和库存照片 |
| `/care-profiles`及权限子接口 | 照护对象、指定照护人 |
| `/medication-plans` | 创建、查询、修改、暂停、恢复、结束 |
| `/dose-occurrences`及确认事件 | 按日期查询，服用／跳过／纠正 |
| `/notification-preferences` | 区分库存提醒和服药提醒、接收人及渠道 |
| `/releases` | 按小程序／Android及发布渠道查询版本说明 |

所有新写入检查家庭和照护权限；编辑使用版本校验，确认使用幂等键。小程序写请求继续使用受支持的 POST／PUT／DELETE。

### 5. 微信与 Android 提醒

**微信实现链路：**

用户点击订阅 → 核实对应模板授权 → 服务端持久化未来事件 → 定时任务检查事件仍有效 → 调用微信发送接口 → 点击消息后鉴权进入计划或库存详情。

- 服药提醒与库存到期提醒使用各自符合业务的模板。
- 页面分别显示"计划已保存、提醒授权状态、发送结果"。
- 一次性授权按实际次数使用；长期提醒以正式账号的类目、模板和平台能力为准。
- 用户必须主动触发授权；不能承诺打开一个开关就永久收到每日提醒。[微信订阅接口](https://developers.weixin.qq.com/miniprogram/dev/api/open-api/subscribe-message/wx.requestSubscribeMessage.html)
- 无合适模板标记 `BLOCKED_PLATFORM`，计划和站内安排仍可使用。
- 默认通知只写"有一项用药安排待确认"，不包含剂量或就诊信息。
- 发送前复核计划状态、接收人权限和确认状态；超时旧事件不集中补发。

**Android：**

- 库存期限和服药提醒分开通知渠道。
- 服药提醒按单次实例安排，核验通知权限及精确闹钟权限；权限不足时显示可能延迟。
- 权限申请由用户开启功能触发，不在首次启动集中索取。
- 改期、暂停、退出和权限撤销后取消相关通知；手机重启后恢复仍有效的安排。
- 通知冷启动跳转、后台和锁屏表现分别实测。精确闹钟需要相应系统权限。[Android 官方说明](https://developer.android.com/develop/background-work/services/alarms)
- 离线提醒依据最后同步数据；另一端修改后，离线手机可能暂未更新，页面必须显示同步时间。

## 四、分阶段实施与后续功能

| 阶段 | 本阶段工作 | 进入下一阶段的条件 |
|---|---|---|
| R0 数据修复 | 复核现有未提交修复，完成恢复保真、身份隔离、编辑和提醒回归 | 高优先级缺陷有行为测试及数据库证据 |
| R1 库存模型 | 毫升／板、确认换算、照片、标签、统一状态与备份兼容 | 双端同一样例结果一致 |
| R2 页面体验 | 四导航、药箱卡片、筛选排序、录入核对、详情、游客引导 | 页面操作、返回、草稿和权限失败可恢复 |
| R3 用药计划 | 照护对象、权限、计划、今日安排、确认与历史 | 双账号代记及并发确认通过 |
| R4 通知和更新 | 微信模板联调、Android通知、版本介绍和更新链路 | 真实送达、点击和取消证据 |
| R5 家庭试用 | 双端整体回归、独立测试部署、两账号两手机完整流程 | 每项验收有明确结果，未通过项不计完成 |

后续按以下顺序扩展：

1. **联网关键词搜药**
   搜药→候选列表→厂家／规格／批准文号核对→加入药箱核对页。复用现有资料适配器，增加分页、来源时间和候选去重。供应商文档注明内容以返回结果为准，处方药说明书可能缺失；查询失败仍可手动录入。[极速数据接口](https://www.jisuapi.com/api/medicine/)

2. **家庭药箱分析**
   先做库存事实：用途分布、临期、缺资料、重复记录，以及用户自己设置的常备清单缺项。不把"没有某类药"直接写成购买或用药建议。分析从"我的"进入，首页最多放一个简短摘要入口。

3. **就诊档案**
   复用照护对象和权限，支持就诊日期、机构、科室、用户记录、处方或检查附件。默认私有，可明确共享；不自动解释诊断。

4. **记录统计与家庭守护**
   统计已确认、跳过、未确认和库存盘点情况，注明记录完整度。以后可加入过敏史、重要联系人和照护摘要；不通过这些记录自动判断健康水平。

积分、连续签到奖励、权益商城和 AI 问诊不纳入这条路线，避免分散药箱与提醒的主要任务。

## 五、验收、交付与默认边界

### 必测场景

- **数量**：12.5ml、零、未知、板片混合、换单位、未确认换算、拆分后总量一致。
- **照片与识别**：拒绝权限、取消拍摄、模糊图片、识别失败、响应乱序、用户清空字段、保存后照片仍可读取。
- **标签与筛选**：多条件组合、未知日期、全部已处理批次、长药名、小屏和大字体。
- **身份**：换账号不串库存或草稿；游客不能读真实数据；邀请跨登录保留。
- **计划**：孩子无需账号、未授权家人访问拒绝、跨日安排、指定星期、改期、暂停、结束、两人同时确认、纠正历史。
- **提醒**：无授权、授权不足、模板不可用、已确认后取消、成员移除、服务重启、手机重启、离线旧安排、通知冷启动跳转。
- **更新**：每版仅介绍一次、下载失败、未保存表单、更新后会话和草稿恢复、App签名与数据兼容。
- **恢复与导出**：新旧备份、标签和小数数量保真、已处理状态保留、私有计划不进入家庭库存导出。

### 工程检查

运行根目录 `lint / typecheck / test / build`、严格真实 PostgreSQL 集成测试，以及 Flutter `analyze / test / build apk`。测试断言实际数据和请求，页面资源存在不算功能通过。

真实验收至少两名微信账号、两台手机，分别完成：

```text
登录／授权 → 创建或加入家庭 → 扫码或拍照
→ 核对保存 → 筛选排序 → 创建计划
→ 收到提醒 → 确认服用 → 修改／暂停
→ 导出 → 更新后再次打开
```

证据使用 `PASS / BLOCKED / NOT_RUN`，绑定具体提交和运行环境。微信模板、真实通知或设备验收未通过，可以交付候选版本，但不宣布全部完成。
