### API：修复退家与邀请／切家的真实锁环

此前并行退家修复先锁账号全部 sessions，随后锁家庭和成员。邀请重放先锁家庭、成员再更新 session；切家先锁成员再更新 session。相反顺序可形成两个真实 PostgreSQL 死锁。

本轮从 PostgreSQL 官方 17.6 源码及 SHA256 校验构建一次性回环测试实例；新回归复用已有真实行锁与 `pg_blocking_pids()` 工具。旧生产实现两例均使退家返回 500，数据库日志明确记录 `deadlock detected`。

生产改动仅把退家顺序调整为**家庭 → 当前成员 → 按 id 排序的该账号全部 sessions → 删除／清理 → 读取 fallback → 修复会话**。会话锁仍在成员删除和 fallback 查询前，保留双家庭并行退出的一致性。新两例加原两例共 4 PASS / 0 FAIL / 0 SKIP，且核对家庭、owner、其他账号会话、库存和邀请消费回执未改。
