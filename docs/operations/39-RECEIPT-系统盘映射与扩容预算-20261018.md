## 新增维护峰值规划

采用获准维护窗口一小时、原镜像和原卷全部保留、备份及隔离恢复暂按同一系统盘计算的保守方案。将来如果批准使用独立恢复位置，可分设备重算，但不能先借另一环境运行真实Owner库。

| 新增项目 | 规划预算 | 口径 |
|---|---:|---|
| 候选tar暂存、载入解包及新写层 | 1.0GiB | 高于当前约80.5MiB tar与镜像本体合计；不能把压缩包当展开峰值 |
| 同点DB+私照备份及校验临时文件 | 0.5GiB | 高于当前约47.7MiB原卷规模，覆盖额外临时/验证副本；真实备份未跑，必须测量复核 |
| 获准隔离恢复集群及新容器写层 | 1.0GiB | 原PG镜像已经存在，保留且不重复计；给恢复数据/验证写入留空间 |
| 新增迁移WAL/临时文件 | 1.0GiB | 规划包络，非实测峰值；原已有WAL已在已用量中 |
| 维护期间共享主机增长及日志 | 1.5GiB | 一小时假设，不对其它项目做删减或修改 |
| **新增峰值预算合计** | **5.0GiB** | 超出任一包络或窗口延长就停止并重算，不承诺绝对上界 |

这里选择 `df` 的空间压力口径：`Used / (Used + Available)`。不能用 `Used / 文件系统总量` 混淆ext4保留/不可用空间，否则会把55GiB误判为达标。

以当前文件系统/原盘比例及保留空间比例估计扩容后大小：

- 当前有效容量比例 `r = (Used + Available) / 原盘字节数`。
- 目标盘下限 `ceil((当前Used/GiB + 5) / (0.80 × r)) = 56GiB`。
- 下表未提前计入删除旧镜像、删除其它项目、释放ext4保留块或迁出原数据取得的空间。

| 目标原盘容量 | 增加容量 | 估计维护峰值df使用率 | 估计峰值后可用 | 达到本次≤80%目标 |
|---|---:|---:|---:|---|
| 50GiB | 10GiB | 88.66% | 5.27GiB | 否 |
| 55GiB | 15GiB | 80.60% | 9.92GiB | 否 |
| 56GiB | 16GiB | 79.16% | 10.85GiB | 是，数学下限，余量较少 |
| **60GiB** | **20GiB** | **73.89%** | **14.57GiB** | **是，建议值** |

40GiB当前可用不足1GiB，不能承受5GiB新增预算。50GiB可能放得下这一预算，但达不到所选的维护后空间压力目标，不写成“任何情况下都无法升级”。估计假定扩容后的文件系统和不可用空间比例接近当前；格式化参数和实际分区扩展结果可能不同，扩完必须重新 `df`。独立只读数学审查已复核最终公式、GiB换算和旧镜像不重复计数；没有执行生产测试。
