## 已完成的方案与实现

### 1. 首页：显示与筛选采用实际参数语义

文件：`apps/miniprogram/pages/index/index.ts`、`index.wxml`。

API 的 `stockStatus.state=unknown` 可能表示未配置低库存阈值或不同单位不可比较，并不等于批次数量未知。旧首页直接以它驱动“数量/日期未知”筛选和“库存待核对”提示，误报了数据完整的药品；没有阈值的全零库存也可能漏掉“已用完”。

现在分别计算活动批次的未知数量、未知管理期限与实物全零状态。已处置批次不影响当前库存；无批次仍需核对。库存不足入口保留 API 的 `low/exhausted`，并补充明确的全零库存；“已用完”要求所有在柜批次均明确为零，不把未知当零，也不把“过期后可用量为零”混同为实物用完。

效期聚合将 `unknown` 放在 `ok` 前，与 API 严重程度一致；过期与未知并存时，主状态仍为过期，同时保留未知筛选。明确的 `managementExpiryDate=null` 不回退为原始未解析日期；仅旧响应缺省管理日期字段时，采用已有包装日期，月精度按月末排序、显示仍保留月份。无效排序 picker 值不会造成选项与排序规则失配。

### 2. 录入：保存的内容与页面操作保持一致

文件：`apps/miniprogram/pages/medicine-edit/medicine-edit.ts`、`medicine-edit.wxml`。

- 提交期间，输入处理、草稿导入/丢弃和原生控件同步保护。保留新建药品原有 `attemptedPayload` 锁，编辑已有药品也不能在旧 payload 提交期间悄悄改变表单并被成功收尾清掉。
- 保存成功后记录新的表单基线；继续编辑会重新启用草稿保留。新编辑、新保存、隐藏或卸载都会令旧 800ms 返回失效。
- 原生返回及首页 fallback 的迟到失败均核对导航序号、页面存活、会话和家庭范围，不跳走新页面、不显示旧提示、不释放新操作的锁。当前返回失败仍可重试；已失去原家庭范围的表单仍可主动离开。
- 单位确认弹窗返回时复核原家庭、批次身份与保存状态。

现有批次 ACK、上传意图、封面版本、识别来源与照片待补机制保留；没有重写照片存储或删除策略。

### 3. 详情：写操作与用户看到的原家庭、原药品绑定

文件：`apps/miniprogram/pages/medicine-detail/medicine-detail.ts`、`medicine-detail.wxml`。

旧照片路径已有严格范围保护，普通写操作仍可能在 `auth/me` 改变当前家庭后继续使用旧药品 ID。现对阈值、补货、开封、拆分、数量、备注添加/删除、归档和删除九类动作统一捕获显示身份、药品 ID 与页面刷新序号。每次确认、认证、写入、回执、异常和延迟导航均检查归属；严格认证不在后台重新交互登录。

离开旧家庭时完整清除详情、备注、阈值、数量面板、拆分输入和忙状态的内存投影，不改原家庭数据。自身请求确认 401 时进入登录页，确认家庭失效时进入家庭入口；外来或过期回执不会导航新页面。重新打开同一药品也会让旧请求收尾失效。

备注与数量面板的旧成功回执只清理本次原输入，等待期间写入的新内容、可见范围或新面板继续保留。备注在派发前阻止重复提交，并用独立 `noteActionSeq` 区分同页刷新与离页：同页其他保存后的读取不能提前解除备注锁，备注自身的 200/403/401 仍可正确收尾；隐藏、卸载或切家后旧备注不能解除新操作的锁。

低库存设置的原生控件、处理函数、单位确认和保存入口同时检查 `savingThreshold || loading`。保护一直持续到保存后的读取完成，覆盖 PATCH 已返回但 GET 尚未返回的窗口；拆分表单原有提交中保护继续保留。

独立静态复核未发现新固定高度裁切或外部资源依赖；没有引入 UI 库、图片资产或新微信能力。此结论不替代 320/390 宽、200% 字号和键盘遮挡的真实微信渲染验收，也不宣称所有未改控件都已满足同一尺寸目标。
