## 2. 真实缺陷、红测与生产修复

### 2.1 用途候选和说明书章节

原实现会从否定句提取正向用途关键词，也可能把无括号的禁忌/注意事项段落并入功能主治。新增回归先失败，再将章节识别限定为明确标题边界，遇到下一已知标题停止；用途按句保守提取，含明确否定、禁慎忌、请勿/禁止/避免/无效等的句子不自动补标签。成分、泛称“感冒”仍不推导具体用途；有效标签去重且最多三项。原说明书内容保留供人工核对，不能把整理标签当作用药建议。

### 2.2 人工清空与多草稿状态

小程序原候选会重新填入用户明确取消的全部用途标签；仅复用页面在途 `touchedFields` 又不足以跨草稿保存/重开保留选择。新增回归覆盖手工勾选后全取消、保存重开、A→B→A、清空后再次识别，再把 `purposeTagsTouched` 随本份草稿持久保存。旧草稿缺字段时兼容为未编辑，另一份草稿不继承本份的人工清空。候选仅填未编辑的空值，先过白名单、去重、最多三项；识别结果也尊重人工清空。

Flutter 原先没有消费候选 `purposeTags`。已在用户明确采纳候选后补入同样的规则，并把用途编辑与人群编辑区分开；更改人群不阻止未编辑用途的正常填充。新增真实 widget 回归同时验证未人工保存前无写请求、未核验状态保留、人工非空/清空优先及多草稿独立状态。原家庭 epoch/成员资格契约未放宽。

### 2.3 标签导出的原型键

原字典索引会把 `constructor/toString/__proto__` 等未知标签当作原型成员。修为只接受自有映射键，未知值保留原文；原 CSV/Markdown 转义及公式防护不变。

## 3. 自主选择并实际实施的下一阶段

现有离线源码准入已覆盖精确 Git 对象、源码树、同 SHA 三项前置 CI、候选校验和反虚假发布状态，本轮保留并重新执行。根据 48 号实际发生的错 Compose 项目名、空数据库栈短暂启动，选择更迫切的 **既有部署身份门禁 + 绑定备份 + 仅 API 替换入口**，没有重新造另一套候选框架。

### 3.1 已交付的工程入口

| 入口 | 实际行为 |
| --- | --- |
| `scripts/build-api-candidate.mjs` | 只从精确 40 位 Git SHA archive 构建；生成 root/API tree、36 份迁移名及校验和的汇总指纹；构建镜像并核对 OCI 来源标签和不可变 image ID；写入独占新回执，避免工作树私密文件进入上下文 |

### 3.2 独立复审实际关闭的问题

产品修复与部署门禁分别由其他审查者交叉复核。除上述业务缺陷外，本轮审查并修复了：Docker 短容器 ID 与完整绑定 ID 混比；探针与正常入口因 DNS/extra_hosts/PGOPTIONS/镜像继承环境不同而连错目标；同一数据库新增同名用户 schema 后默认建表位置变化；解析后 Compose 配置被再次展开 `$`；Docker env-file 与 Compose env-file 语法混用；备份 DB 容器内 libpq 环境污染；合成 DB 的 PGPORT 同时改变服务监听；负例断言把普通工具故障误算成预期拒绝。回归分别覆盖这些实际边界，没有通过删断言使测试变绿。

卷名/创建时间负例是审定元数据不符测试，不声称实际删除并同名重建了卷。实际建立了第二套独立数据库，分别验证无迁移账本及“迁移齐全但没有家庭内容”的同形空库不能匹配原实例身份。所有 Docker 破坏性操作受 hosted CI、唯一随机资源名、所有者标签和完整身份账本限制；不传生产凭据，不用全局 prune。

2. `backup-docker`：原双家庭配对备份恢复和新增部署身份门禁的真实隔离 Docker 测试均成功，检查实际产物中的源 SHA/镜像/实例及合成内容摘要。

4. `candidate-delivery`：仅在前三项同 SHA 成功后生成源码候选；独立下载并校验 ZIP 字节、manifest package 指纹、root/mini tree、build 10 与 run ID，再重算 readiness。`releaseAllowed` 仍为 false。

最终 SHA 和对应四项绿色结果必须来自一次固定源码交付；中间红测和其他 SHA 的历史成功不混用。PR #7 的最终回执同时给出可点开的 job/artifact 链接，接收时先核 branch HEAD 与 PR HEAD 再核每个 run 的 head_sha。

### 首轮真实 Docker 反馈与继续修复

首个完整实现提交 `56e718e74df0ce6fd407f1496365ea06e2c01233` 的 [push run 40163904199](https://github.com/Jovifei/Medcial-box/actions/runs/40163904199) 在原备份步骤的数据库身份读取处失败：`Invalid database probe JSON`。PostgreSQL 的 `json_agg(record)` 可输出跨行 JSON，原读取逻辑只取以 `{` 开头的第一行，错误截断了含 36 份迁移的结果。合成资源按完整身份清理成功，新增替换步骤没有执行；该 SHA 不满足四绿交付条件。

根据这个真实 CI 失败，在本轮回环 PostgreSQL 17.6 用只读事务和合成 `generate_series` 取得 36 行合法 JSON，保留多行迁移账本回归。旧生产实现实际 45 PASS / 1 FAIL，修复后 47 PASS / 0 FAIL；另覆盖截断和尾随杂字必须拒绝。psql 改为 quiet 模式抑制 BEGIN/COMMIT 状态行，对完整 stdout 做严格 JSON 解析，不删除迁移核验、不宽松截取字段、不吞解析异常。修复后继续跑新固定 SHA 的完整 CI。精确源码小程序 QA 在 56e 上另有 39 PASS / 0 FAIL / 0 SKIP，新提交不修改 mini tree，但最终仍重新绑定自己的 SHA。

此修复经过另一位审查者只读复审；本机完整 tooling 重跑为 251 项：235 PASS / 0 FAIL / 16 Windows 平台 SKIP，完整 lint 再次 exit 0。首次完整验证表的 233 项通过保留为该时点记录，不冒充增加两项回归后的计数。
