## 3. 选择的下一完整阶段

**既有部署身份校验、绑定备份与仅 API 受控替换入口。** 48 号记录的 Compose 项目名错配不是仅靠文档即可消除的问题：普通命名卷允许自动新建；现有备份只固定 API/照片卷，未固定数据库容器与数据库实例。

保持现有 Node/Bash/Docker 技术路线，不新增运维平台和生产依赖。具体实现：

1. 人工审定的本地绑定文件记录 Docker/Compose 项目、API/DB 容器身份、原 DB/私照卷身份与挂载、既有网络、DB 实例/数据库/迁移指纹。自动发现只能生成待核资料，不能自行把错误空栈登记为通过。
2. 默认只读 preflight。所有缺项、错项目、多容器、卷替换、错库、连接目标漂移、候选来源不匹配均在危险动作前拒绝；输出仅脱敏状态，不打印环境或凭据。
3. 受控替换入口重读实时状态，并固定 `-p`、既有 external 卷/网络及不可变镜像 ID，仅更新 API，禁止该入口创建 DB/新卷、拉镜像或执行隐式 build。候选在运行正常入口和迁移之前用只读探针确认目标 DB。
4. 备份复用同一身份核验，按固定 DB 容器 ID 采集，并在前后复核；保留原停写、配对、只读照片和原子发布机制。身份不明时不发布假成功备份。
5. 镜像增加完整 revision/source tree/API tree 来源元数据。元数据及本地 binding 不是签名或生产授权，需与独立构建/CI 回执核对；API URL 和 ready=connected 不证明来源。
6. 仅在隔离的合成 Docker 栈运行错项目、同形空库、卷身份不符、配置污染、来源错配、漂移和合法 API 替换/配对备份验证。卷名/创建时间负例属于绑定元数据不符，不冒称已物理删除并同名重建卷；清理只针对本次创建且身份匹配的资源。

Docker 操作不是原子全局锁；维护窗口仍需排除外部 writer 和并发管理员。门禁保障的是受控入口，不能声称阻止绕开入口的 Docker 管理操作。

### 实施中经回归确认的调整

原计划复用 `touchedFields` 足以挡住同一在途识别请求，却不能跨照片草稿保存/重开区分人工清空。新增失败回归证明后，小程序和 Flutter 均把 `purposeTagsTouched` 作为本份草稿的持久字段；旧草稿缺省为未编辑，切到另一份草稿不继承前一份的人工清空。识别请求仍保留原有在途字段保护。部署复审另补入实际数据库 schema/search path、容器端连接环境污染与候选镜像环境继承校验，避免身份探针通过而正常入口实际连到另一目标。
