# 固定候选接收与分层验收

本指南只准备源码候选，不会部署 API 或上传/发布微信。接收人使用 PR #6 最终回执中的 40 位 SHA；不能使用浮动分支名作为验收身份。

## 1. 保护本地并接收

先保存并核对 `E:\project\medcial_box` 的 git status/diff 与已有未提交补丁。不要 reset --hard、clean 或强推；原 login/medicine-edit 补丁不能直接覆盖。建议在新的、尚不存在的独立 worktree 验证：

```powershell
$sha = '<PR6最终回执中的40位SHA>'
git -C E:\project\medcial_box fetch origin codex/medbox-106-p1p3-20261023
git -C E:\project\medcial_box merge-base --is-ancestor f802c8f2b6ae1549f0348bc3b65fa4dcf327fbb5 $sha
# 上条非0即停止核对，不能自动继续。
git -C E:\project\medcial_box worktree add --detach E:\project\medbox-pr6-acceptance $sha
```

worktree 已存在就另选新的目录；不得删旧目录凑命令。新目录只接收代码，不复制真实 .env、家庭照片或生产数据库。

## 2. 源码与候选包

在独立目录执行 `npm ci`、`npm run lint`、`npm run typecheck`、`npm test`、`npm run build`，记录实际 PASS/FAIL/SKIP。需要真实 PostgreSQL 的部分使用隔离合成资源；不得指向现役库。Flutter analyze/test 和 Android 构建由独立环境验证，未签名包不能覆盖用户手机。

候选构建和再核验：

```powershell
node scripts/candidate-bundle.mjs build --sha $sha --appid wx1f6dd99d28aab8e5 --api-base https://medbox.joviluma.com --output var/acceptance-candidate
node scripts/candidate-bundle.mjs verify --sha $sha --appid wx1f6dd99d28aab8e5 --api-base https://medbox.joviluma.com --output var/acceptance-candidate
```

也可下载同 SHA CI 的 `medbox-source-candidate-<SHA>` artifact，在固定源码 checkout 下对其中 `bundle` 目录运行相同 verify。检查 artifact 自身 digest、manifest.sourceSha、sourceTree、miniTree、client、version、files 与 packageSha256。清单哈希不代替 GitHub 上该提交的 CI 和代码审核。`ci-receipt.json` 是无签名的作业结果记录，不能离线当作可信签名或官方平台回执。

该工具不接触配置中的 HTTPS 服务；只有实际打开开发者工具并操作客户端才会产生业务请求。未授权真实家庭测试前，只做静态检查和合成验证。

| 层级 | 要核对的证据 | 未完成时禁止声称 |
