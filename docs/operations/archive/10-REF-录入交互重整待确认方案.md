# 录入交互重整待确认方案

2026-10-04。Jovi 已确认并授权执行。实现与验证结果见 11-RPT-录入重整与识别验证.md；真实手机验收仍单独记录。

## 页面顺序

1. 拍药盒/扫码：识别期间显示中央等待面板及已等待秒数，明确超时/失败与重试；不显示虚假进度百分比。
2. 包装信息核对：药名、品牌、厂家、包装规格。每盒多少粒与药效持续小时数分开；识别不清留空。商品码显示来源，扫描码和资料库返回码冲突时不静默覆盖。
3. 家中库存：用户实际数量和单位；有效期一行，按包装原精度展示中文年月或年月日。点日期即可修改，无独立常驻精度下拉；未知时选择器默认年月，可切换年月日，不能将月份编造为某一天。
4. 用途/人群：默认可见，AI依据可见包装或说明书提供可编辑用途建议，人群只依据明确标签，不由药名推断。空值保留待确认，不能为填写表单猜适用人群。
5. 存放位置：独立折叠选填；批号及开封资料归到库存更多资料，位置只出现一次。
6. 说明书：独立拍照入口，原图可查看；识别成用途、用法、禁忌、注意事项草稿，由用户核对后保存，不覆盖用户改写内容。

## 共用交互

- 全部新建/编辑日期复用 medicine-date-field；时间建立共用 time-field，用时间选择器添加、编辑及删除多个提醒时点，禁止要求手写 HH:MM。
- 新标签候选：止痒、眼部、口腔、便秘、腹泻等。须统一契约、后端白名单、双端选择与筛选，不能仅增加客户端按钮。
- 盘点：说明它将实际剩余与账面核对；改为每药卡片，保留正确/修改余量/用完/稍后核对，解释操作效果。
- 我的页面：当前家庭卡片、提醒与计划、数据导出/备份、帮助/设置分组，保留原权限和导航逻辑。

## 已核查问题

- 小程序邀请码 POST 未提供 payload，但通用请求始终声明 JSON。需要请求层与实际网络复现，验证空 JSON body 修复，而非归因邀请码权限。
- 商品资料目前依赖 Jisu provider，缺配置或供应商失败与无匹配必须区分；尚未验证当前提供商密钥是否可用，不新增付费服务或编造药品资料。
- AI 服务能返回 purposeTags，录入页未将该返回字段同步到选中 chips。
- 存放位置在分类块和批次补充信息重复；计划编辑仍有手写时间输入。

## 验收

使用实际药盒样本区分12小时/20粒；完整执行拍照等待、核对、保存、第二药空白、说明书复核、邀请码创建和加入、盘点保存、计划多个提醒时间选择。模拟器与手机分别记录，不将 UI 编译或 Provider 配置存在当真实验收通过。
