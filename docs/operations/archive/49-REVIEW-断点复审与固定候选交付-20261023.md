## 实际下一阶段：可验证、不可误发布的源码候选交付

新增 `scripts/candidate-bundle.mjs` 和回归测试，并在原 CI 三作业之后增加 `candidate-delivery`。不是仅增加计划文件：工具真正从 Git 对象读取指定 40 位提交、生成独立 HTTPS 小程序工程、校验它、生成绑定提交的清单和 CI 前置作业回执，再上传 GitHub artifact。

设计与实现边界：

1. 不复制工作树：脏文件、未跟踪文件、测试、密钥和本地配置不进入候选。生产路径采用固定白名单；非普通 Git blob、符号链接和未知类型拒绝。
2. 只替换公开客户端 AppID、API origin、候选名称和启用的域名校验；不请求该 API、不读取账号凭据。版本来自同一提交 VERSION.json。
3. 每文件记录 SHA256 和字节数，清单记录 root/mini tree、源码 SHA、版本、AppID、HTTPS origin 和整体指纹。输出目录独占创建，不覆盖已有候选或备份。
4. verify 重新从受信的明确 Git SHA 计算期望文件和配置，而不是相信产物自己声明的哈希。缺失、多余、变更文件、篡改清单及符号链接全部拒绝。原小程序静态包门禁再次运行。
5. CI 必须等 verify、backup-docker、flutter 全部 success；新作业只打包与上传 artifact。回执明确是 `UNSIGNED_CI_RECEIPT_NOT_A_SIGNATURE`，不是签名证明或平台验收。工作流最终成功须回 GitHub 核验。
6. 微信官方编译、上传、体验版、双家庭真机和 Android 安装均为 NOT_RUN；部署为 NOT_PERFORMED，正式发布为 NOT_AUTHORIZED。不能因静态包门禁通过就提交微信正式发布。

工具的定向测试覆盖可复现构建、脏树隔离、错误 SHA/AppID/origin、文件增加/删除/篡改、清单篡改、已存在目录、符号链接、未知生产文件、HTTP/凭据 URL、失败门禁及 CI 前置结果。Windows 不具备普通符号链接创建权限时两项 symlink 测试明确 SKIP，Linux CI 执行它们；SKIP 不计 PASS。
