- 适用端：微信小程序（`apps/miniprogram`）、Flutter App（`apps/flutter`）、Web 桌面端（`apps/web`）。规则全项目通用，其他项目 UI 交付可参照执行。
- 优先级：业主终审决定 > 本标准 > 各端既有 DESIGN.md/设计文档。冲突时停工问业主，不擅自取舍。

## 1. 设计令牌（唯一事实来源，成套写死）

原则：令牌成套定义、按名引用；每端各持一份落地映射表；页面内禁止新写散装 hex、字号、圆角。确需新值时先补令牌再使用。

### 1.1 色板

浅色现行值（已上线，两端一致）：

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| background | `#F2F2F7` | 分组页面背景 |
| surface | `#FFFFFF` | 内容卡/信息分组 |
| inset | `#F2F2F7` | 列表内衬、缩略图底 |
| label | `#1C1C1E` | 主文字 |
| secondary | `#636366` | 次要文字、图标线 |
| line | `#DCDCE1` | 输入框/描边 |
| accent | `#087F5B`（深色 `#30B58B`） | 唯一强调色：主按钮、选中、链接 |
| accent-tint | `#EDF6F2` | 选中底 |
| success / warning / danger | `#146C43` / `#8A5700` / `#B42318`（各配 tint 底） | 状态语义色 |

规则：

- 强调色全项目只一个（品牌绿），不铺内容区、不做大面积色块、不做装饰渐变。
- 危险/警告/未知状态必须「语义色 + 明确文字」双通道，不只靠染色；日期未知不得显示为效期正常，数量未知不得算作 0。
- 禁止自造高饱和 hex、禁止彩色大底色块。
- 【待业主拍板】业主 2026-11-08 家庭健康台基线要求**暖纸底**，与现行冷灰 `#F2F2F7` 不同。v0.1 不改值；待业主给出目标色值，或授权起草方提交 2–3 个候选（每个附与 label/secondary 的对比度计算值）后，在 v0.2 固化并两端同步。影响面：两端 background/inset 及卡片观感。
- 深色：Flutter 端已定义全套深色（`AppSemanticColors` 双套），小程序端当前仅浅色一套。规则定为**深色是标准要求、各端必须成对实现**；小程序深色落地排期与验收截图范围【待业主拍板】（涉及全部页面的变量与回归）。

### 1.2 字阶

- Flutter：沿用 `DESIGN.md` 中文紧凑档 11 级（28/24/20/18/16/15/14/13/12/11，headline 16 用 600 字重），禁止阶梯外字号；层级靠字号+字重，不靠颜色；全部文本随 textScaler 缩放。
- 小程序：现行两级并存——全局 4 阶 rpx（标题 36、正文/输入 30、次要 26、辅助 22）+ 页面级 px 细分（大标题 28、区块 18、行主文 16/600、辅助 13/12/11，见 `index.wxss` 实值）。
- 字体：系统中文栈 PingFang SC / Noto Sans SC；**禁止 Inter/Roboto**，不引入外部字体资产。
- 大字号：主要文本一律可换行，行高 ≥1.4，容器高度自适应；禁止固定高度截断，禁止靠关 text scaling「通过」截图。
- 【待确认】小程序 rpx 阶与 px 阶并存属历史现状，v0.2 应收敛为单一 rpx 阶+换算表；此项动全量页面，列为独立任务待业主批准后排期。

### 1.3 间距与网格

- 8pt 网格（px 端）/ 8rpx 网格（小程序），4 为细分；标准间距 8/12/16/24。
- 页面左右边距 16–20；卡片内边距 16；列表行距 8–12。
- 大留白原则（业主基线）：区块间以留白分隔为主、弱化分隔线；总览页留白 > 详情页。
- 底部安全区：`env(safe-area-inset-bottom)` 必算；底部留白随字号放大用 em（现行 6.5em 做法保留，与 medicine-detail 一致）。

### 1.4 圆角

- 现行：控件 8px（16rpx）、卡 12px（`app.wxss .card`；注释口径 24rpx）。
- 业主「大圆角白卡」方向：卡圆角候选 16–20px【待业主拍板具体值，两端同步】。规则：同屏同层级圆角必须一致；禁止「万物大圆角」与全屏巨圆角。

### 1.5 阴影与材质

- 现行：内容卡无阴影（`box-shadow: none`），层级靠分组背景与分隔。
- 规则：内容层默认无阴影；确需浮起（悬浮按钮、弹层）用单档 `0 1px 4px rgba(0,0,0,0.06)`，数值以计算/实测为准，不许目测调参。
- 玻璃/模糊只许导航与控制层；**内容层禁止假玻璃**（现行约定保留）。

### 1.6 图标与触控

- 线性图标、单风格（SF Symbols 风，现行 CSS 画线做法可保留）；禁 emoji 当图标，不混两套风格。
- 命中区最低 44×44、目标 48×48（现行小程序控件 min 48px；Flutter 目标 48）；小程序端按 px 实测达标，rpx 名义值不作为触控依据。

## 2. 组件与版式规则

### 2.1 三栏任务分工（业主 2026-11-08 基线）

- 左 = 人的上下文（家庭/照护对象、身份与状态）；中 = 视觉锚点（当前事项全貌/主视图）；右 = 事项与行动（待办、动作入口）。
- 总览给全貌，一点进单项详情；总览页不嵌详情级操作。
- 窄屏（手机 320–402 宽）纵向堆叠顺序固定：上下文 → 锚点 → 行动，顺序不得随页面改变；Web 桌面端三栏常驻。
- 【待确认】现双端首页为单栏列表。三栏基线优先约束家庭健康台总览与 Web 桌面端；存量单栏页是否改造、何时改造不在 v0.1 范围，交叉评审后列排期报业主。

### 2.2 导航与选中态

- 主导航稳定：药箱 / 用药计划 / 我的 三栏（双端现行）；不为风格增加第四 Tab。
- 胶囊导航（业主方向）：主导航用现行两端 Tab 体系（Flutter CupertinoTabBar、小程序原生 tabBar）；页内分段/筛选逐步统一为胶囊控件。
- 黑色选中态【待业主拍板】：现行筛选 chip 选中 = 绿描边+绿字+tint 底（`filter-chip.selected`）。业主基线「单一强调色 + 黑色选中态」存在两种读法——(a) 选中态一律黑色（黑底白字或白底黑胶囊），强调色只留主按钮/链接；(b) Tab/分段选中黑、动作选中绿。请业主明确语义范围；确定后两端同步改并重跑窄屏回归。

### 2.3 状态呈现

- 四态不可混淆（T3 M1 口径，已上线）：空数据 / 首次加载失败 / 有缓存的刷新失败（stale 提示「暂时无法更新药箱」）/ 加载中。
- 操作反馈：按钮忙碌期防重复提交；记录成功在原条目回显；失败或结果不确定保留重试语义，不伪造成功。
- 日期语义：切到他日标题与空态以选定日期为准并提供「回到今天」；不把「这一天无安排」说成「从未创建计划」。

### 2.4 表单与列表

- 强左对齐（现行全局规则）；空态、弹窗与底部动作按钮视觉居中。
- 必填校验反馈落到具体输入框；草稿保护、旧回执失效等业务约定 UI 不越权改动。
- 列表行主信息一行可辨（药名/规格/余量/效期/位置），次信息 12–13px；badge 允许换行，不得溢出卡片。

## 3. 各端适配

### 3.1 微信小程序（WXML/WXSS）

- 令牌经 page 级 CSS 变量（`--med-*`）引用，字面 fallback 保留供独立组件；新页面禁止新造色值。
- 原生组件优先；`scroll-view` 等标签必须过 QA 白名单门禁——**任何角色不得修改白名单或放宽断言自我放行**。
- 微信分享 `open-type="share"`、订阅消息按平台能力使用；不绘制假系统控件、不仿制 iOS 状态栏。

### 3.2 Flutter App

- Cupertino 组件优先；视觉参数对齐 `apps/flutter/DESIGN.md`；残留 Material 层必须无波纹（NoSplash）。
- 颜色只经 `AppSemanticColors` 取用；动效统一走 `app_motion`（200–350ms，只动 transform/opacity，无目的不加动效）。

### 3.3 Web 桌面端

- **不得把移动版式等比拉宽充当桌面版**（业主明确）。桌面版按三栏任务分工重排：左右栏定宽、中栏自适应；窄于断点回落到移动单栏版式——断点数值【待确认】。
- 桌面端不得新增两端没有的业务入口；共享 API 与数据契约不变。
- 【待确认】`apps/web` 现状与三栏目标版式的差距盘点未做，v0.2 补差距表。

## 4. 参照工作流（参照先行，#346 四法落地）

1. **先给参照再写 UI**：写界面前先交参照（现有页面截图/参考稿/同业截图），写明沿用点与偏离点；无参照不开工。
2. **逐元素对齐并声明偏差**：对参照做元素级清单（尺寸/色/字/距），每处偏差写明原因；不许「大概像」。
3. **设计令牌成套写死**：按第 1 节执行；页面不发明新值。
4. **候选收敛业主拍板**：多方案并陈时附计算数据，业主选定后写入本文件新版本。
5. **生成物过门禁再提交**：按第 5.5 节；门禁拒绝时如实报告失败，不得改白名单/放宽断言/跳过检查自我放行。
6. **拿不准先问业主**：含「估算/待确认」的交付物必须先报业主决定，不得当作定稿流转或进入终审。

## 5. 验收清单（几何核对优先；真机优先于合成预览）

### 5.1 几何与版式核对（业主 2026-11-08 令）

- 所有尺寸/间距/圆角/字号必须给出**计算式或实测值**，附《几何验证表》，列为：条目 / 规则值 / 实测值 / 来源（计算式或 DevTools·模拟器读数）/ 偏差 / 结论。
- 禁止目测估算；「估算/待确认」未清零不得进入业主终审。

### 5.2 响应与字号矩阵

- 宽度：320 / 327 / 360 / 390 / 402（小程序实机口径，T3 专项沿用）；Web 桌面另验断点上下两态。
- 字号：100% + 200%（或系统最大档）双档必验；大字号下无截断、无重叠、可滚动、尾部控件可见。
- 窄屏专项（T3 口径回归）：日期独立不可断行；≤360px 余量/效期上下排列；筛选 chip 单行滚动；底部 em 留白随字号放大；搜索占位缩短。

### 5.3 状态与可及性

- 四态区分截图（空/首载失败/刷新失败 stale/加载中）；危险·警告·未知三态文字+色双通道。
- 对比度抽查用计算值：正文 ≥4.5:1、大字/图形 ≥3:1；普通大小彩色文本单独核对。
- 触控尺寸核对表；已实现深色的端附深色成对截图。

### 5.4 证据层级（不可互相替代）

真机截图 > 微信开发者工具/官方模拟器截图 > 合成渲染测试 > HTML 对照稿。每份证据注明工具与版本；HTML 参考稿永远不替代真实端验收。

### 5.5 门禁条目（提交前全绿；失败不提交、保留现场）

- 根 `npm run lint` + `npm run typecheck`；小程序 `node --test` 全量；`check:miniprogram:source` 源码包门禁；`prepare:mini:qa` + `test:mini:qa` 隔离 QA；候选包 `check-miniprogram-package`（release 模式）；官方 `wcc`/`wcsc` 编译；Flutter `analyze` + 定向测试。
- 版本纪律：版本递增、微信上传、部署、合并 main、推送授权一律是业主授权动作，本标准不授予。
