## 身份、授权与数据范围

微信登录凭证由服务端 `WechatGateway` 交换为本应用会话；客户端请求携带会话令牌。API 通过会话和当前家庭成员关系获取服务端授权上下文，每次数据操作都在该上下文内检查家庭边界。创建、接受邀请、退出或切换家庭会使旧家庭请求失效；客户端也在异步读取、登录和文件操作前后核对身份代次，避免旧响应覆盖新账户状态。

家庭库存由药品资料、独立包装批次、有效期、数量/单位、位置和可见性不同的个人剂量备注组成。产品规格（如 20g）与批次库存计数单位分开保存；计数单位 `tube` 表示“支”，数量必须为整数。相机或资料接口产生待确认内容；识别草稿和库存写入是不同步骤。说明书资料不构成面向个人的用药建议。

## 计划创建与确认重试

`POST /api/v1/medication-plans` 接受可选幂等键。客户端为一次创建保留原始请求意图；用户显式重试时沿用相同键和载荷。API 在同一事务中锁定操作范围、重新检查家庭成员及照护授权，再查询回执：

1. 尚无回执时创建计划、时间点和不可变响应回执。
2. 相同家庭、用户、键和规范化内容再次提交时返回原响应，不重复创建计划。
3. 相同键携带不同内容时返回冲突，要求用户核对已保存记录。
4. 若写入结果未知，读取恢复状态不会自动重放；用户必须明确选择重试原请求或在核验后开始新操作。

迁移 `028_medication_plan_create_receipts.sql` 新建 `medication_plan_create_receipts`，以家庭、用户和请求键唯一定位回执，并保存规范化内容哈希及创建响应。迁移 `029_tube_quantity_unit.sql` 将“支”加入计数单位白名单，并扩展数据库校验约束。尚未部署这些版本的环境，必须先应用所有待用迁移（包括 `028`、`029`），再更新 API，然后更新客户端。

服药确认采用同类显式操作键，避免响应丢失后产生重复历史事件。确认已经被服务端接受后，随后刷新计划/通知失败不得撤销确认，也不得变成第二次创建。

## 提醒发送与授权边界

提醒调度器在发送之前复核当前成员关系、接收偏好、药品/批次状态和本次租约归属。`send_started_at` 是外部消息调用前的持久边界；一旦越过边界，超时、进程退出或数据库结算失败都不能自动被当成“确定未送达”而重发。发送结果不确定时保留诊断状态，等待后续核对。用户关闭授权或成员/对象失效时，未开始的旧任务应被取消或阻止。

“只接收提醒”权限使用最小提醒投影；提醒和跳转不因此解锁药名、剂量或计划历史。真实模板送达、锁屏/后台通知和系统重启行为仍须在真实设备验证。

## 导出文件生命周期

导出内容根据同一份授权快照生成，默认不包含个人剂量备注。Flutter 的临时文件管理登记当前进程创建的文件并维护分享租约，账户或家庭身份失效时清理本应用明确拥有的文件。系统分享副本、接收方副本以及无法证明归本应用拥有的文件不应按宽泛目录规则删除。跨进程残留和任意进程终止后的清理仍是单独的验收项。

## 数据库迁移与门禁

迁移编号当前延伸到 `030`。其中 `027_inventory_reminder_send_boundary.sql` 为库存提醒记录增加发送开始/取消边界；`028_medication_plan_create_receipts.sql` 保存计划创建回执；`029_tube_quantity_unit.sql` 加入“支”单位；`030_medicine_brand_and_purpose_tags.sql` 增加品牌字段并扩展用途标签约束。迁移为增量文件，已经应用的 SQL 不应回改；生产部署顺序为数据库迁移、API、客户端。

