# 产品需求：家庭药箱

记录家庭实际持有的药品和包装／批次，降低维护库存与有效期的成本，并导出清楚、可核对的上下文供用户交给外部 AI。

## 目标用户与目标

- 首版由 Jovi 的一个家庭使用，家庭成员加入同一个共享药箱。
- 用户可以知道家中有哪些药、分别剩多少、放在哪里、何时到期。
- 相机识别形成可确认的录入草稿，而不是直接改动库存。
- 用户可核对药品资料来源，或补拍说明书、手动补全。
- 用户按需导出 `.md`，交给自己选择的外部 AI。

## 首版行为

1. 打开药箱时，首页显示库存、临期和过期计数，并支持按名称和用途搜索。
2. 新建一条药品资料，再为包装批次逐项记录数量、单位、有效期和存放位置。相同药品不同日期的盒子保留为独立批次。
3. 数量可以是未知，也可以是已知的零。包装单位转换成片、粒或袋前必须确认换算数量。
4. 日期保存原始精度：年月格式保持 `YYYY-MM`，不补造某一天；缺失日期标为待补充。默认提前 30 天显示临期，过期和耗尽状态分别提示。
5. 说明书字段与某位家人的实际用药备注是不同信息。识别和联网补全可以生成草稿，必须经家人确认后保存；禁止根据同名药、常见剂量或用途自动生成个人剂量。
6. 每条药品卡片左侧展示名称、规格、库存和有效期；右侧展示用途摘要。点开后查看说明书摘要、来源、核对状态和原始材料。
7. Markdown 导出包含导出时间、药品资料、批次数量与有效期、已确认的说明书用途、用法用量、禁忌和注意事项摘要，以及来源和核对状态。缺少的字段标为待补充；默认不包含个人剂量备注，用户预览后可选择加入。导出不作服药建议。
8. 导出内容写成 UTF-8 `.md` 本地文件；微信端通过 [`wx.shareFileMessage`](https://developers.weixin.qq.com/miniprogram/dev/api/share/wx.shareFileMessage.html) 分享本地路径，同时提供复制文本作为替代路径。接口要求本地或临时文件路径；`.md` 真机分享仍需 P3 实测确认，开发者工具预览不能代替验收。

## 录入识别流程

手工输入或拍照 → 后端创建识别任务 → 回传候选草稿 → 使用批准文号、厂家、规格核对资料 → 用户确认或编辑 → 才写入药箱。未匹配、不完整、规格冲突或接口失败时允许手填并标注缺失来源；不能因为识别失败而丢弃可手工维护的库存。

## 页面

- 药箱首页：临期／过期提示、搜索、分类和批次库存。
- 药品录入：手动填写或拍照获得待确认字段。
- 药品详情：资料来源和说明书摘要、每批次库存、家庭成员剂量备注。
- 家庭管理：成员、邀请和角色。
- Markdown 导出：选择字段、预览、复制和分享文件。

## 首版不包含

应用内问诊／推荐服用、服药打卡、自动扣库、用药提醒通知、多个家庭注册运营、处方审查或医疗档案。这些范围不影响 P0 的启动验证。

## 验收指标

- 用户能通过手工方式维护药品和不同批次，即使外部数据服务不可用。
- 拍照识别结果可编辑且未经确认不会进入药箱；信息来源可见。
- 数量未知、零、不同日期批次与年月精度在列表和导出中保持一致。
- 一个家庭的非成员无法读取或修改其药箱。
- Markdown 能独立阅读、含有不确定状态，并且不把有库存写成适合服用。
- 至少一台真实微信客户端成功分享 `.md`；若当前客户端不接受该文件，复制文本仍能交给外部 AI。

## 安全说明

照片可能包含个人信息，只上传用户明确选择的图片。家庭成员可以共同看到家庭库存和说明资料；个人剂量属于家庭健康信息，记录与导出单独控制。删除和备份在 P4 定义数据保留流程。
